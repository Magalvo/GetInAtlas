## Approach

The principle is **one gate, many folders**. `make check`, the pre-commit
hook and CI keep running one typecheck, one lint and one test run, and those
runs now also cover `packages/*` and, later, `apps/*`. No per-package scripts
and no TypeScript project references yet: with one package, they add setup
without adding safety. They become worth it when the API and web apps need
separate builds (WI-0016 and the PWA skeleton).

1. **Workspaces.** The root `package.json` gains
   `"workspaces": ["apps/*", "packages/*"]`. `apps/` stays empty in this
   item. The npm scope is `@getinatlas/` (see the questions below).
2. **`packages/domain`:**
   - `package.json`: `@getinatlas/domain`, private, `type: module`. `exports`
     points `types` at `src/index.ts` and `default` at `dist/index.js`.
   - `src/index.ts` holds a single placeholder, `domainPackageName`, typed as
     the literal `'@getinatlas/domain'`. It carries no domain logic (out of
     scope). It exists only to prove that the package builds, exports and is
     imported.
   - `src/index.test.ts` sits next to the code it tests.
   - `tsconfig.json` extends the root config, includes `src`, and sets
     `"types": []`. The domain therefore sees no Node types, so importing
     `fs` doesn't even typecheck when building the package.
   - `tsconfig.build.json` emits to `dist/` and excludes `*.test.ts`. The
     root `.gitignore` already ignores `dist/` at any depth.
3. **One command per check, three callers.** Today `make`, `lefthook.yml` and
   `ci.yml` each repeat `npx eslint src tests scripts`. Adding `packages`
   would mean editing three places now and again for every new folder.
   Instead:
   - the root `package.json` scripts become the single definition:
     - `lint`: `eslint src tests scripts packages apps --no-error-on-unmatched-pattern`
     - `typecheck`: `tsc --noEmit`
     - `test`: `vitest run`
   - the Makefile, lefthook and CI call `npm run lint`, `npm run typecheck`
     and `npm run test`. A new workspace then needs no change to any gate.
4. **Typecheck and tests cover the workspaces:**
   - the root `tsconfig.json` `include` gains `packages/*/src/**/*.ts` and
     `apps/*/src/**/*.ts`;
   - `vitest.config.ts` `include` gains `packages/*/src/**/*.test.ts` and
     `apps/*/src/**/*.test.ts`.

   Nothing is relaxed: the strict options stay in the root `tsconfig.json`,
   and the domain inherits them.

5. **Boundary rule (AC3).** A new block in `eslint.config.js`, scoped to
   `packages/domain/**`, adds `no-restricted-imports`. It forbids:
   - `node:*`, `fs`, `net`, `http`, `https` and `child_process`;
   - any path containing `/apps/`;
   - `@getinatlas/api` and `@getinatlas/web`.

   This adds a rule and disables none (AGENTS.md hard rule 3).
   `types: []` in the domain's `tsconfig.json` is the second layer.

6. **Docs.** The AGENTS.md structure table (`packages/` for the pure domain,
   `apps/` for deployable apps) is **not** updated here. It moves to the
   first item that creates `apps/` (the owner chose option (a) below).

## Risks and edge cases

- **ESLint `lintText` with the project service** may refuse a `filePath`
  that isn't on disk (it is "not found in any project"). Fallback: the test
  writes a temporary `packages/domain/src/__probe__.ts`, lints it and removes
  it in `afterEach`.
- **`--no-error-on-unmatched-pattern`** also hides a typo in a folder name.
  It is acceptable, because the AC2 test asserts the exact folder list.
- **`npm ci` on the CI runner** with a workspaces lockfile needs npm 7 or
  later. Node 22 ships with npm 10.
- **The domain's `exports` point at `.ts` for types.** That works for
  `tsc --noEmit` and Vitest. A runtime consumer (the API, WI-0016) will need
  the built `dist/`. WI-0016 adds that build step, and this item doesn't
  pretend to solve it.
- **The adopter CLI build** (`tsconfig.build.json`, `rootDir: src`) must
  stay unaffected. Its `include` doesn't change.
